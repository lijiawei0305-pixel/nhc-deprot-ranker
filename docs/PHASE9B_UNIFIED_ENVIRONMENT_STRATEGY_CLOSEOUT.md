# Phase 9B Unified-Environment Strategy Closeout

## Decision

This is an irreversible provenance decision, not a dependency diagnosis:

```text
unified_environment_strategy = closed_after_u5
closure_reason               = frozen_attempt_policy
technical_coexistence         = observed_but_no_validated_identity
```

There will be no U6 and no further unified-environment attempt. U1 through U5
remain immutable evidence:

| Attempt | Terminal state | What it established |
| --- | --- | --- |
| U1 | `failed_incomplete_environment` | exact stack installed and imported; the preregistered calculator-call metrology and durable-evidence contract did not close |
| U2 | `rejected_environment` | package, import-order, native-map, endpoint capability, cache, network, and four-call calculator gates passed; protected-snapshot schemas were asymmetric |
| U3 | `failed_before_environment_creation` | the qualified snapshot helper rejected normal Conda launcher symlinks |
| U4 | `failed_before_environment_creation` | the symlink policy was corrected, but CLI-dependent capture failed without sufficient portable command diagnostics |
| U5 | `failed_before_environment_creation` | metadata-native qualification failed while loading the helper, before any protected-object capture or v005 creation |

U1 and U2 prove that the software stacks can coexist technically: exact
artifacts installed, both import orders exited normally, native mappings were
classified compatible, and the AIMNet2 endpoint smoke completed. U3 through U5
failed in environment-qualification metrology or its remote harness. Therefore
none of these results supports the statement that AIMNet2 and PySCF are
incompatible.

At the same time, no attempt produced a validated unified-environment identity.
Each published attempt prohibited repair, replay, reinterpretation, or reuse,
and U5 explicitly froze split-process design as the successor if Q5 failed.
Creating U6 would contradict that published boundary.

## Retained value

The attempts remain useful evidence for artifact compatibility, import order,
native-library compatibility, calculator invocation semantics, cache and network
isolation, symlink-aware launcher identity, and failure modes in environment
metrology. Their prefixes, wheelhouses, caches, logs, and receipts retain their
original status and are never execution inputs.

## Successor

The only successor architecture is the dual-environment, split-process assisted
route specified by `PHASE9B_SPLIT_PROCESS_RUNTIME_PLAN.md`. This decision does
not authorize implementation, server access, source re-baselining, deployment,
launch, Postflight, or scientific computation.
