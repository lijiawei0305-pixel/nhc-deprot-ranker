## Retained U4 fact and U5 design ruling

U4 proved that all six objects passed launcher authentication and the Python
probe, then returned `CONDA_EXPLICIT_FAILED`. Its portable receipt did not
retain the exact command substage, return code, or stderr. The concrete command
failure therefore remains unresolved: it may not be guessed or reconstructed.
U4 did not prove that any protected environment's contents were defective; it
proved only that CLI-dependent capture did not qualify.

U5 no longer needs that external command to succeed. Protected identity is
derived from the prefix's own persistent bytes: launcher/executable,
`conda-meta/history`, every `conda-meta/*.json`, every installed `*.dist-info`,
and the prefix tree. Package-manager CLI output is neither authoritative nor a
blocking observation.

## Document-first and Q5 gates

Before any SSH, the U5 helper, tests, inventory schemas, qualification V3
contract, and this plan must pass all local gates and merge to `main`. Q5 then
permits one controlled SSH and no server write. The exact merged helper captures
A/B for project MLFF, project AIMNet2, project GPU-PySCF, shared molecular,
unified v001, and unified v002. It invokes no package-manager CLI, imports no
computational package, uses no GPU, downloads nothing, and creates no v005
resource.

Every capture must be `present`, have `failure=null`, retain a stable
root-contained launcher and Python identity, and produce identical raw/normalized
Conda inventories, distribution inventory, tree identity, canonical projection
bytes, and projection SHA256. Any failure terminates U5 as
`failed_before_environment_creation`; the exact object, stage, code, assertion,
and partial evidence are retained. There is no helper edit, retry, relaxed
object set, U6, or v005 creation. A helper-design failure permanently ends new
unified-environment attempts and routes future design to a dual-environment /
split-process assisted route.
